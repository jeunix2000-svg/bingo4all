ポイント・マイクロサービス

YFC 社内 Wiki の 採点・ランキング・不正防止 を担う独立マイクロサービス（ADR-002）。

📄 DDL: yfc_points_service.sql をダウンロード

設計方針（4 原則）​

  1. point_events = 追加専用台帳 (append-only ledger) — 唯一の真実の源泉。ISMS/監査ログに適合。
  2. 残高/評価 = 派生集計 — award_points() が同一トランザクション内で同期更新。
  3. 不正防止 (anti-gaming) — 自票禁止 / 日次上限 / 評価者評価の重み付け / 相互いいね検知 / 低品質ペナルティ。
  4. 質 > 量 — 基本点は低く、主な得点は他者評価・採択・参照から。ルールはデータ化 (point_rule)。

スキーマ構成​

区分テーブル説明
A. マスタuser_type, category, post_type, level_def, badge_def, point_rule参照・採点ルール
B. ミラーapp_user, post, contributionWiki 側の最小ミラー
C. 評価vote, value_rating投票・多軸評価
D. 台帳point_event追加専用・真実の源泉
E. 集計user_point_balance, user_domain_reputation, user_badge, gaming_alert派生データ

コア関数 award_points()​

採点の核心。同一トランザクション内で：

  1. ルール取得（無効化時は 0 点）
  2. 受益者決定（SELF / TARGET_AUTHOR）
  3. 不正防止①：自己操作禁止
  4. 不正防止②：日次上限
  5. 評価者評価の重み付け（0.5〜1.5）
  6. 台帳計上（UNIQUE による重複防止）
  7. 残高 + レベル更新
  8. ドメイン評価更新（≥800 で検証者資格）
